# Career Assistant MVP PRD

## 用户问题

求职者通常无法判断自己的简历事实是否完整、与岗位要求的差距在哪里，也难以验证 AI 建议是否基于真实经历。

## MVP 用户流程

1. 用户录入简历文本。
2. 用户录入一个岗位描述。
3. 系统提取事实并展示来源片段。
4. 用户确认、修改或拒绝事实。
5. 系统基于已确认事实生成匹配分析。
6. 系统输出简历修改建议与面试准备清单。

### 多岗位比较流程

1. 用户录入同一公司的多个岗位及投递数量限制。
2. 系统解析毕业年份、学历、地点、出勤等硬性条件。
3. 系统只使用已确认的候选人事实，分别列出匹配项、可迁移优势、缺口和风险。
4. 系统将岗位分为“推荐投递 / 可以冲刺 / 不建议”，并给出可解释的维度分数。
5. 系统按投递限制返回前 N 个岗位，同时保存岗位链接、采集时间和分析版本。

## 核心数据对象

- CandidateDocument：候选人文档。
- JobDescription：岗位描述。
- EvidenceSpan：来源文本及位置。
- CandidateFact：教育、工作、项目或技能事实。
- ReviewDecision：用户确认、修改或拒绝。
- Recommendation：基于已确认事实生成的建议。
- JobRequirement：岗位的硬性要求、核心要求或优先条件。
- MatchAnalysis：岗位资格判断、维度分数、证据映射、缺口和推荐等级。
- ApplicationRecord：岗位来源、分析时间、投递状态和后续动作。

## MVP 验收标准

- 每条事实必须关联至少一个来源片段。
- 未确认事实不得被表述为确定结论。
- 无证据时返回“信息不足”，不得补造经历。
- 10 组测试样例可以重复运行并记录结果。
- Java API 与 Python AI 服务均有健康检查和基础自动化测试。
- 匹配分数必须返回维度拆分，所有“已匹配”结论都能追溯到已确认事实。
- 多岗位模式能在指定投递上限下输出排序结果，并解释未入选岗位的主要原因。
- Java→Python 调用能观测请求量、成功率、错误数和延迟，日志不包含完整简历或联系方式。

## 非目标（当前 MVP）

- 不承诺绕过登录、验证码或招聘网站反爬机制。
- 不自动代替用户提交申请。
- 不使用无法解释的单一向量相似度作为最终匹配结论。
- 不把计划学习或未完成项目当作已经具备的能力。
